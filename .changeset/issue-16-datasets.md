Add a speech dataset registry and fetcher (issue 16): `datasets/registry.json` lists FLEURS (en, ru, hi, zh), the AISHELL-3 test transcripts and two LibriVox recordings with recorded sizes and SHA-256 checksums, and `datasets/refused.json` names corpora that must not be added. `npm run datasets -- list|fetch|verify` downloads a small part of a dataset into the ignored `.datasets/` cache with resume, retries and a size limit, and refuses any licence that is not in `allowedDatasetLicences` of `scripts/policy-denylist.json`. `npm run check:policy` reports registry errors and tracked cache files under rule `dataset`; the heavy-checks workflow caches `.datasets`.

Add the manually started workflow `Heavy checks` (issue 14) for tests that are too slow for every pull request. Such tests live in `tests/heavy/`, named `<suite>-<topic>.test.js`, and run only through `npm run test:heavy -- [--suite <name>] [--limit <n>] [--out <dir>]` (`scripts/run-heavy.mjs`), which writes `reports/heavy/summary.md` with one row per test file and shows it in the run summary; `bun test` and `deno test` now skip the folder. The first heavy test reports the render time and the real-time factor of every audio tier except `reference`. `.gitignore` now ignores only the `reports/` folder at the root, so that kept reports can be committed to `docs/reports/`. The workflow's optional `ref` input accepts a branch or tag of this repository, or a commit already on the default branch (`scripts/resolve-heavy-ref.sh`), so that a run cannot put code from a fork into the default branch's cache. The library itself does not change. (This branch is stacked on the issue 14 pull request, so its changeset is folded in here: the release check allows one changeset per pull request.)
