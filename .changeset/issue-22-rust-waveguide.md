Render the waveguide tiers in the Rust engine (issue 22). The biquad, the LF glottis, the baffled radiation, the waveguide with its nose, piriform branch, frequency-dependent losses and yielding walls, the noise sources, the output stage, the per-step loop of `VoiceRenderer`, the microphone and the room are ported to `crates/voice-simulator-core` (`filters.rs`, `glottis.rs`, `radiation.rs`, `waveguide.rs`, `losses.rs`, `stages.rs`, `renderer.rs`, `listener.rs`, with the `Solver` trait in `solver.rs`). JavaScript still plans the utterance and shapes the tract once per control block (`blockShape` of `voice.js`, shared with `VoiceRenderer`) and hands Rust one configuration array and one frame per block; the layouts are `RENDERER_CONFIG`, `FRAME` and `LISTENER` of `src/engine/layout.js`, which `tests/engine-layout.test.js` compares with `config.rs`, `frame.rs` and `listener.rs`. The package exports `loadEngineModule`, `ENGINE_ABI_VERSION`, `RustVoiceRenderer`, `renderPlanRust` and `renderJob`; options the engine does not handle throw with `code === 'ENGINE_UNSUPPORTED'`. The WebAssembly module gains `vs_renderer_new`, `vs_renderer_render`, `vs_renderer_position`, `vs_renderer_field`, `vs_renderer_free` and the component exports of the parity tests. Measured with `REQUIRE_WASM=1 node --test tests/rust-waveguide.test.js`: every render (`minimal`, `low`, `medium`, a studio room with a microphone, chunks of 1, 37 and 1024 samples) matches JavaScript with a largest difference of 1.7e-18 (one-ulp differences of `pow` in the loss filter design); chunking gives identical samples. `voice-simulator-cli render-job <file>` renders a job of `scripts/write-render-job.mjs` natively and prints the same SHA-256 as the WebAssembly render. The heavy test `performance-rust-waveguide` measured the Rust renderer 1.5 to 2.0 times faster than JavaScript on every waveguide tier. The WebAssembly file is 93300 bytes against a new budget of 98304.
