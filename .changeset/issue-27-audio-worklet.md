Play streamed speech through one AudioWorklet node (issue 27). The new export `voice-simulator/playback` holds `PLAYER_PROCESSOR_URL` and `PLAYER_PROCESSOR_NAME` of the processor module `src/playback/worklet-processor.js` and the ring buffer functions (`createRing`, `ringWrite`, `ringRead`, `ringEnd`, `ringReset`, …). The processor plays its input as one continuous stream, fades one 128-sample block out on an underrun, counts it and fades in again when samples arrive. `createStreamResampler` resamples chunk by chunk; joined, its outputs are those of `resample` with the same filter. The example app plays through `WorkletPlayer`: a SharedArrayBuffer ring when the page is cross-origin isolated (`VITE_CROSS_ORIGIN_ISOLATION=1` sets the COOP and COEP headers), the message port of the node otherwise, and buffer sources when no AudioWorklet loads; the HUD shows the mode and the underruns. Measured in headless Chromium and Firefox (`experiments/issue-27-latency.mjs`), the player adds at most 21.4 ms against 110.2-150.4 ms for buffer sources, a 36-42 s paragraph plays with 0 underruns, and under a 6x CPU throttle the underruns are counted with no click. The resampler is ported to the Rust core (`vs_resample*` and `vs_resampler_*` exports, error code -6 `BAD_ARGUMENT`) with class B parity tests that measured a difference of 0 on Node.js, Bun and Deno; the WebAssembly file is 33260 bytes against a new budget of 49152.
