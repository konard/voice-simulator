Make the Rust engine the default, with JavaScript as the fallback (issue 25). New `createEngine()` and `getEngine()` give an engine object (`name`, `simd`, `threads`, `reason`, `createRenderer()`), and every renderer it makes tells which engine renders it (`renderer.engine`) and why it is not Rust (`renderer.fallbackReason`). `synthesize`, `synthesizeAsync`, `synthesizeStream`, `renderPlan`, `renderPlanAsync`, the benchmark and the HTTP server take `engine: 'auto' | 'rust' | 'js'` (default `'auto'`: Rust when `voice-simulator.wasm` loads, else JavaScript), `threads` and `simd`. Use `engine: 'js'` for byte-stable output, because the two engines differ by up to 1e-4 per sample. The CLI takes `--engine` and `--threads`, `benchmark` prints the engine (`"engine"` with `--json`), and the server accepts `engine=js` per request. The synthesis worker is exported as `voice-simulator/worker`. It answers `{type: 'engine'}` and tags each utterance with its engine. The loader names the wasm with a literal `new URL(…, import.meta.url)`, so bundlers copy it. The example app's settings panel shows the engine and has an Engine setting (Auto, Rust, JavaScript).
