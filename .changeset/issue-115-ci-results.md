Fix the false CI results found in issue 115. The changed-lines lint now reports warnings in whole changed files, like the pre-commit hook, and the `Waveguide` constructor no longer trips the complexity limit. Dependency review is skipped with an explicit message when the repository's dependency graph is disabled. ShellCheck now covers every tracked script, and the scripts it flagged are fixed. Python files are linted with pinned Ruff. The Rust job fails on compiler, Cargo manifest and rustdoc warnings. The workflows, scripts and tests follow the JS pipeline template again. The example app drops deprecated packages, its previous versions install only the web build dependencies, and it measures its chunk limit in UTF-8 bytes, so oversized chunks are no longer missed. Its pronunciation dictionaries load as a separate chunk. The engine loader reads `node:fs/promises` without a specifier that bundlers replace with an empty stub, which removes the Vite warning. Onset rules are chosen with a `switch` instead of an object lookup, so a language name that matches an inherited `Object.prototype` property can no longer call it. The expected WebGPU fallback warning is asserted in its test instead of printed into the log. The artifact-transport action locks a `fast-xml-parser` release without the GHSA-474x-hrwr-fgx4 advisory. Secrets are scanned with secretlint 14, which has the recommended rules built in, so CI no longer installs the deprecated preset package. The Bun and Deno test suites get the 300s budget of the Node.js suite: Bun runs its files one after another and Deno is slow on Windows, so both were close to the old 200s limit. Budget warnings and errors now start on a new line, so GitHub keeps them as annotations when a test leaves its output without a final newline.
